# Public reviews and the local review agent

The review feature combines a public feedback wall, a pretrained sentiment classifier that runs in
visitor browsers, a reply for every accepted review, and an admin-only human-labelling/distillation
workflow. It requires no AI-provider API key and makes no hosted inference call.

## What players see

- `#/reviews` is readable while signed out. Firestore permits public reads only from
  `reviews/{reviewId}`; every client write is denied. The page shows the chronological feed in
  24-review pages, the highest-scoring review prominently, and the reply attached to each review.
  The home page reuses that spotlight after review data has been loaded; it deliberately makes no
  startup database request, preserving the app's network-free first paint.
- A player may submit as a guest or account. The browser runs sentiment inference first, then the
  callable validates a 1–5 rating, game id and text, rate-limits to three submissions per account per
  day, creates the automatic reply, and atomically writes the public review and a private owner map.
- Public records do not contain a Firebase UID. `reviewOwners/{reviewId}` is backend-only and lets
  account deletion remove authored reviews, their admin training labels and the active distilled
  model. Reviews also expire after one year; cleanup removes their private records and resets a
  model that may have learned from them.
- The spotlight score gives star rating priority; review detail, game context and named topics break
  ties. It is a clearly-labelled editorial sort, not a vote or claim that the review is objectively
  best.

## Pretrained on-device sentiment model

The primary classifier is [`Xenova/distilbert-base-uncased-finetuned-sst-2-english`](https://huggingface.co/Xenova/distilbert-base-uncased-finetuned-sst-2-english), pinned to revision
`0b6928efcb76139cae2c6881d49cda67fe119f42`. The browser loads it with Transformers.js and quantized
`q8` ONNX weights in a module worker. It is a genuine pretrained DistilBERT model fine-tuned for the
binary Stanford Sentiment Treebank v2 (SST-2) task, whose short sentences are movie-review-domain
text. It is not trained on PSD-gaming reviews, not fine-tuned for games, and not a three-/five-star
product classifier. Its positive/negative output is combined with the star rating and a transparent
lexicon; low-confidence output falls back instead of being presented as certain. Strongly conflicting
stars or clear positive and negative wording are marked mixed.

The quantized ONNX weight file is roughly 67 MB (plus small tokenizer/config files). We do not commit
or bundle those weights with the site. On first use, the browser requests the pinned static model
files from Hugging Face and its file CDN, then Transformers.js caches them in browser Cache Storage
for later visits (the browser may evict that cache). This is a real third-party network request: the
model host can see the requested file and ordinary connection metadata such as the visitor's IP
address. The request does not include review text, and the model host does not run inference. The
review text is only submitted to this project's Firebase callable when the player chooses to post.
There is no AI inference endpoint, provider API key, or review-text upload to Hugging Face. The
quantized ONNX Runtime WebAssembly engine is instead served from this site on demand with the worker;
the current bundled threaded runtime is about 27 MB uncompressed (roughly 6.7 MB gzip) and is cached
as an immutable app asset. So the first model use transfers more than the 67 MB weights alone. If the
weights cannot be fetched or the browser worker cannot run, the Firebase function still replies using
the local lexicon and small curated synthetic starter fallback.

This model should improve general English positive/negative classification over a tiny hand-built
cold-start sample, but no game-review accuracy is claimed. It can miss sarcasm, slang, mixed feedback,
non-English text, game-specific jargon, and context that SST-2 did not teach it. The UI and privacy
notice disclose the first-use download and the dataset/domain limitation before posting.

## Replies and fallback analysis

Every accepted review goes through `createReview` before its public Firestore write. The function
attaches one respectful, context-aware reply template based on the sentiment and named topics. Replies
are not generated by a language model: they are deterministic server-side copy, do not claim a human
has read the review, and do not promise that a fix has shipped. Firestore rules deny direct writes, so
a review cannot be published through the normal client path without its reply.

`shared/reviews/agent.js` is shared by the browser and Cloud Functions. It validates the submitted
model id, immutable revision, sentiment label and confidence before using the compact prediction
envelope. It does not download weights or make network requests. In addition to the transformer, the
agent uses a small inspectable word lexicon with negation/contrast handling, the player's star rating,
and product topics such as connection, bugs, mobile controls, instructions, rooms/invites, variety,
difficulty, accessibility and audio. If the transformer is unavailable or uncertain, that local
logic and the synthetic starter remain as a functional no-provider fallback; the starter is not a
substitute for the pretrained model or a claim about actual players.

## First-party data distillation

A model cannot honestly be described as trained on PSD-gaming feedback until people have submitted
reviews and an operator has checked the labels. The admin **Review agent** tab keeps that workflow
separate from the pretrained model:

1. The assistant assigns a provisional label as each review arrives.
2. An admin inspects the public text and selects a human-checked positive, negative, mixed or neutral
   label. Those labels live in the private `reviewAnnotations` collection, not on the public review.
3. Once there are at least two labelled examples in each of two sentiment classes (four examples in
   total), **Distill labeled reviews** trains a compact multinomial Naive Bayes student from the
   actual, first-party review text and those corrected labels.
4. The model document keeps only class priors and a bounded table of token log-likelihood weights.
   It does not retain review text, display names or user IDs. When its confidence is high enough, this
   first-party model specializes the general transformer; otherwise DistilBERT leads.
5. If account deletion or one-year expiry removes source reviews, the active human-trained model is
   cleared so it can be retrained without those examples. The curated synthetic starter fallback
   remains and is still identified as synthetic.

Admin improvement ideas are deterministic and evidence-counted: recurring topics in negative and
mixed reviews are mapped to concrete checks, with the number of supporting reviews shown beside each
idea. With no recurring complaint, the panel explicitly says there is not enough evidence to
prioritize a fix. These are review-triage suggestions, not automated product decisions.

## Deployment

The browser model uses `@huggingface/transformers`; its weights are fetched on demand rather than
included in the Vite output. Vercel installs with `npm ci --ignore-scripts` because the app never uses
the package's native Node ONNX runtime; this avoids its unnecessary native-binary postinstall fetch.
`vercel.json` allows only the required Hugging Face static model hosts in `connect-src`, allows the
app-created module worker, and permits WebAssembly compilation for ONNX Runtime. Review text is not
sent to those hosts.

The review feature also uses the existing Firebase project, rules and Cloud Functions deployment.
Publish the updated `firestore.rules` and deploy functions with:

```sh
firebase deploy --only firestore:rules,functions
```

The `functions` code imports a generated copy of `shared/**`; `firebase.json` runs the sync script
as a predeploy hook. No new secret, provider API key, hosted inference endpoint or environment
variable is needed.
